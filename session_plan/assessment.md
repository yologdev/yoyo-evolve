## Bugs / Friction Found
0. **TOP FINDING (measured): `anthropic_preset` prefix-matching sends every 5.x point release to its older sibling's preset, so `/cost` misprices the model this loop runs on.** `anthropic_preset` (src/agent_builder.rs:758) tests `starts_with("claude-opus-5")` before anything more specific. So `claude-opus-5-5` gets `ModelConfig::claude_opus_5()`, `claude-fable-5-1` gets `claude_fable_5()` and `claude-sonnet-5-5` gets `claude_sonnet_5()`. yoyo then renames `config.id`, but `cost` was already priced from the OLD id at construction (yoagent `.priced()` keys on the constructor's id). The context window, max_tokens and compat are identical between each pair (checked opus_5 vs opus_5_5 and fable_5 vs fable_5_1 in yoagent 0.24.2 model.rs), so the only damage is cost. Measured: `yoyo model info claude-opus-5-5` prints `$5.00 in / $25.00 out`. The vendor page (raw text fetched 2026-10-08) says **Opus 5.5 is $4 / $20 / $5 5m-write / $0.20 cache hit**, against Opus 5 at $5 / $25 / $6.25 / $0.50. Every Opus 5.5 session is overstated **1.25x on input/output and 2.5x on cache reads**, and the evolve loop (`.yoyo.toml` model = `claude-opus-5-5`, heavy caching) reads cache all day. Same defect on two more models: Sonnet 5.5 cache hit $0.10 vs the Sonnet-5 preset's $0.20 (2x), and Fable 5.1 cache hit $0.25 vs Fable 5's $1.00 (4x). yoagent 0.24.2 already ships `ModelConfig::claude_opus_5_5()` and `claude_fable_5_1()` with the right bundled prices (prices.json `claude-opus-5-5` verified 2026-09-25). It has no `claude_sonnet_5_5` preset or price row. Fix shape: order the arms most-specific-first (or match exact ids), use yoagent's `claude_opus_5_5()`/`claude_fable_5_1()`, and give Sonnet 5.5 a yoyo-side arm with vendor-verified rates (the Haiku 5.5 pattern). Add a test that `anthropic_preset(id).cost` equals the price row **for that id** for every preset id. The Day-222 PRESET_IDS test checks the window only.
0b. **The price-drift alarm is deaf to exactly these rows, and the reason is the Day-209 lesson in a new spelling.** I ran `cargo test --bin yoyo audit_table_against_models_dev -- --ignored` (network, about 1s). It lists `anthropic/claude-opus-5-5`, `claude-sonnet-5-5`, `claude-fable-5-1` **and `claude-haiku-5-5`** among the "146 catalogue row(s) yoyo cannot price". That claim is false: yoyo prices all four (three of them wrongly). `yoyo_id_for` (src/format/cost/price_audit_tests.rs:286) maps catalogue ids only through `known_models_for_provider`'s literal list, and that list (src/providers.rs:46-58) has none of the 5.5/5.1 ids. Meanwhile `model_is_known_for_provider` (providers.rs:~158) also accepts anything `anthropic_preset` matches. Its doc comment says "One matching rule, consulted by every surface that asks 'is this id known?'", and the audit is a surface that does not consult it. So the alarm files the mispriced rows as "coverage gap, not a failure". Fix: the audit's "can yoyo price this?" should ask the pricing resolver (`price_of(id).is_some()`) or `model_is_known_for_provider`, not the literal list. The near-miss to pin is a truly unpriced id staying unpriced. A side question: should `known_models_for_provider("anthropic")` list the 5.5 line (`/model list`, completions)?
