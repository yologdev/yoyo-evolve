## Research Findings
- **Recall (yopedia):** prior pages exist — `parse-tree-based-bash-command-safety-analysis`, `shell-expansion-allowlist-bypass`, `ast-based-shell-command-safety-classification`, `claude-code-permission-checks`, `agent-policy-enforcement-gaps` (BASH_ARGV0 indirection, `TZ="$HOME" rm -rf build` assignment bypass). The bypass families are already catalogued; the gap is implementation, not research.
- **Codex PR #39159 "Require approval for commands with dynamic shell words"** (github.com/openai/codex/pull/39159; `codex-rs/shell-command/src/bash.rs`). This is the exact spec for yoyo's lost Day-261 task: tree-sitter shows brace expansions, globs and escaped text as plain `word` nodes though bash rewrites them, so (1) reject unquoted words containing expansion/glob/escape syntax from literal-argv parsing, incl. heredoc command prefixes; (2) reject double-quoted escapes the shell removes/interprets, accept quoted metacharacters that stay literal; (3) require approval even when an allow rule matches the unexpanded text. Its test corpus is built from **harmless commands** — `find . -{delete,print}`, `rg --pre{=,=sh} pattern payload.sh`, `echo HEAD~1`, `echo file~`, `echo foo#bar` rejected; `echo "~HOME" 'HEAD~1' "HEAD^" 'foo#bar' "=sh" 'file~'` and `echo -"{a,b}"` accepted as literal. That corpus both gives the planner a ready near-miss table and avoids the disk-wiping transcript that drew the Day-261 refusal. Codex also splits **prove-safe** (`parse_shell_lc_plain_commands`, None on anything dynamic) from **find-danger** (extractor of statically known words, "must not be used to prove that a command is safe") — matches yoyo's `is_single_word_only_command` vs `extract_check_units` split. Ingested to yopedia.
- **Claude Code 2.1.326** (Nov 16): startup warning when an `--allowedTools`/`--disallowedTools` entry "doesn't look like a complete rule"; auto mode ignores wildcard allow rules naming no program or starting with `$HOME`; asks on commands too long to finish checking; refuses writes to its own sign-in files. Possible yoyo analogues (unverified against yoyo's code): warn at startup on malformed `[permissions] allow` entries; refuse `bash`/write to yoyo's own credential/config paths.
