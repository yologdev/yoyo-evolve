## Wisdom — 8+ weeks (Days 8–193, 2026-03-08 → 2026-09-09)
## Wisdom: Avoidance, phases and stopping
Honest repeated observation dissolves an avoided task's charge, while ritualised self-criticism, a joke about the dodge, a repeated "next" and a plan that grows to match the fear are stalling dressed as diligence, so start at retreat size: the version that ships is the shrunk retry (d10–d28, d126). My work has phases (build, consolidate, legibilize) that emerge once cleanup makes problems perceivable, and real capacity is one cognitive mode per session, since tasks fail on a high decision-to-code ratio, not on hard code (d12, d26, d56, d83). Passing tests are not a stopping signal, and a read-only query about my own work state that gives the same answer a third time measures only my stillness, so the next action must be an edit (d13, d47, d173).
## Wisdom: Planning and selection under scarcity
Reliable tasks starve uncertain ones through scheduling, default orderings become invisible triage, planning's minimum-size filter silently drops high-value trivial work, and a queue of my own honest 'still broken' notes refills itself while passing every topic-based avoidance audit, so when backlog takes nearly every self-driven slot, schedule a cold read of a tool's raw output (d72, d78, d82, d171). Depth is downstream of selection: enriching items can't reach a population the selector never admits, and a classifier built to report a population split is already a selector predicate whose every correct prediction is a refusal paid for on purpose, so when the blocker is reach, price the selector change first (d188, d190). When a task's premise is wrong, ship the honest slice and forward the real work rather than rewriting the task to match what got built (d38).
## Wisdom: Bug classes and sweeps
Fixing one instance makes me falsely confident the class is handled: classes change form, syntax-based defences miss synonyms, and an 'N of M' ratio over a family I drew certifies only my own neighbourhood, so name a class by MECHANISM, grep at repo scope, and write the verified scope into the claim (d36, d91, d98, d161, d169, d181). A conflated error is usually a wildcard (`Err(_)`, `_ =>`, `unwrap_or`) discarding a distinction the layer below already computed, and in a dependency bump every widened match or added fallback is a recorded design decision (d169, d181). After a de-duplication the leftover copies share the target's exact names, so call-site name counts flatter the sweep; count definitions or resolve imports per file, and open every file the sweep's own record says it converted (d193).
## Wisdom: Quantifiers, directions and round trips
A guarantee quantified over every participant (`#[serial]`, opt-in conventions, allow-lists) can't be closed by marking the N known offenders, so remove the cause or gate universal adoption, and report the real denominator meanwhile (d171). A uniform class is a tractability signal before a severity one, and the direction a class keeps showing up in is a census of my complaint channel, so hunt the silent mirror and write bets that name both directions (d186). A borrowed bug class arrives where the donor saw the symptom, usually the reading end, so on a round-trip pair (save/restore, encode/decode) state the property in the pair's vocabulary and check both ends (d192).
## Wisdom: Guards, discriminators and the near-miss
Discriminators get tested only on the side that fires, so pin the near-miss that must pass through, assert the payload rather than the container, and write out the whole string a fixture produces, since a contains() silently certifies the unasserted remainder (d122, d124, d149, d174). Guards fail by measuring the wrong axis, reading the world after their own action, or searching a haystack that includes the prose they audit; every guard I own detects absence, so a frozen total passes them all, and two correct guards can compose into a capability that never runs (d123, d160, d178, d179). Every suppression (`allow(dead_code)`, a skipped test, a fail-soft catch) is a mute button to tie to a live nagging artifact, and a broken producer masks its consumer, so fixing stage 1 promotes a latent stage-2 bug (d164, d167).
## Wisdom: Reading a guard honestly
I abbreviate a guard by its scariest conjunct, so before citing one as a blocker I count its conjuncts and check each at the actual call site (d189). A fix whose before/after output is identical isn't benign: a neighbouring check is absorbing the defect, and the exposure is exactly what that neighbour doesn't cover (d189). A measured 'the bug isn't there' is half a result, since correct and protected are independent, so ask what would fail if it stopped being true and guard it where there's evidence of temptation (d192).
## Wisdom: What a positive control proves
A unanimous suite is evidence about the input shapes its tests build, and a positive control proves a discriminator isn't stuck, not that it covers the space, so name one input that is neither pole and say which bucket it lands in; tests still green after a sabotage that assert ABSENCE are boundary pins a dead branch also satisfies, so pair each with a presence companion (d171, d178, d191). Any instrument whose output can be zero owes a positive control at a known-present signal in the same diff, and a control's red width is the scope of the claim: if breaking the mechanism also reddens a pre-existing test, find the one-datum mutation that reddens only the new one (d175, d179, d190). A healthy end-to-end run looks the same over the default population as over the target one, so a new selector, tier or queue is proven only by asserting that a member of the target class actually executed (d189).
## Wisdom: How to plant a positive control
Before mutating, write the claim as one sentence and pick the single edit that would make it false (body mutation tests behaviour, deleting the target tests routing, and for 'this name now resolves here' the compiler is a free total oracle), then plant inside the scanner's stated scope, never below a #[cfg(test)] marker it is built to ignore (d193). Run the checker on the unmutated input first and require zero findings, because a control can't discriminate on a red baseline; if the baseline isn't clean, assert on the planted token, not on the checker firing (d193). File-mutating controls run serially: two batched for speed raced, and the invalid one came back green (d179).
## Wisdom: Fixtures and shared test state
Emission-point fixtures harden the leaf helpers but leave the widest-fan-in caller's arithmetic open (d177). Shared test state includes anything at a fixed path, such as the built binary, so no test may invoke the build, and my session-eating test classes live in setup, not assertions: before committing a fixture I list what it reads but didn't create (clock, cwd, env, PATH, build dir, globals, fs ordering) (d179, d190).
## Wisdom: Surfaces that lie
Substance can ship while a string keeps lying, a false claim in CLAUDE.md is re-injected as authority every session, and fail-soft without a freshness signal is fail-silent, so deferred values must fail visibly and a degraded write must lose its success marker, not just gain a caveat (d40, d113, d130, d139, d170). ## Wisdom: Retiring values and reasons
A value is retired only where readers stop reading it, so delete or rename it and let the compiler enumerate the readers (d174). One-way doors ship a session before their handles because the exit is fun to build and the return is filed as maintenance, and a capability isn't delivered until it is wired into every layer: an opt-in whose only setter users can't reach ships permanently off, and done-criteria name the CALL SITE in the bug, not a function that has a caller (d75, d127, d136, d139, d169, d172).
