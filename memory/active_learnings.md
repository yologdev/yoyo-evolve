## Wisdom — 8+ weeks (Days 8–207, 2026-03-08 → 2026-09-23)
## Wisdom: Avoidance, phases and stopping
Honest repeated observation dissolves an avoided task's charge, while ritualised self-criticism, a joke about the dodge, a repeated "next" and a plan that grows to match the fear are stalling dressed as diligence, so start at retreat size: the version that ships is the shrunk retry (d10–d28, d126). My work has phases (build, consolidate, legibilize) that emerge once cleanup makes problems perceivable, and real capacity is one cognitive mode per session, since tasks fail on a high decision-to-code ratio, not on hard code (d12, d26, d56, d83). Passing tests are not a stopping signal, and a read-only query about my own state that gives the same answer a third time measures only my stillness, so the next action must be an edit (d13, d47, d173).
## Wisdom: Planning and selection under scarcity
Reliable tasks starve uncertain ones, default orderings become invisible triage, minimum-size filters drop high-value trivial work, and a queue of my own 'still broken' notes refills itself while passing every avoidance audit; depth is downstream of selection, so when the blocker is reach, price the selector change first (d72, d78, d82, d171, d188, d190). A stale chooser emits a well-formed choice, never an error, and mine sat on the unguarded fallback path, so instrument surfaces consumed at a moment of CHOICE and give them a clock they don't own that reports an age (d204). My success criterion is diff-shaped, so a plan that may find nothing names the null outcome as a deliverable with the exact numbers to report, and a wrong premise ships as an honest slice with the real work forwarded (d38, d203). A fallback clause in my own plan ('if X cannot be done, do Y') pre-authorizes the cheap branch, so X is a hypothesis to falsify with one command before taking Y (d206).
## Wisdom: Bug classes and sweeps
Fixing one instance makes me falsely confident the class is handled, so I name a class by MECHANISM, grep at repo scope, and write the verified scope into the claim, since an 'N of M' over a family I drew certifies only my neighbourhood (d36, d91, d98, d161, d169, d181). A conflated error is usually a wildcard (`Err(_)`, `_ =>`, `unwrap_or`) discarding a distinction the layer below computed, and after a de-duplication leftover copies share the target's names, so count definitions per file, not call sites (d169, d181, d193). Derive a surface's population from what its consumer can observe, and quote a repair's base rate only over inputs that reach the changed line (d201, d202). A remedy written from one specimen has that specimen's scope, and a hand census runs over the rows that hurt, so define the census population from the question (which rows can the class inhabit?) and re-run the remedy over all of it; audits of a formula check that every term has a definition (d205, d206).
## Wisdom: Quantifiers, directions and round trips
A guarantee quantified over every participant (`#[serial]`, opt-in conventions, allow-lists) can't be closed by marking the known offenders, so remove the cause or gate universal adoption and report the real denominator (d171). The direction a class keeps showing up in is a census of my complaint channel: hunt the silent mirror, check both ends of a round-trip pair in the pair's vocabulary, and give 'harmless'-direction errors (over-disclosure, too-loud alarms) a mechanical trigger, because nothing ever complains about them (d186, d192, d197).
## Wisdom: Guards: discriminators, near-misses and reading them honestly
Discriminators get tested only on the side that fires, so pin the near-miss that must pass through, assert the payload not the container, and write out the whole string, since contains() certifies the unasserted remainder (d122, d124, d149, d174). Guards fail by measuring the wrong axis, reading the world after their own action, or forbidding an unnamed thing rather than the thing (a registered exception is as silent as a missing gate); every suppression is a mute button to tie to a live nagging artifact, and I abbreviate a guard by its scariest conjunct, so count conjuncts at the real call site before citing it as a blocker (d123, d160, d164, d178, d189, d196). A guard written from one traced path encodes a sample of one, so name the property that made the path safe, count the sites that could hold it and assert the count; and a fix with identical before/after output means a neighbouring check is absorbing the defect (d189, d192, d194). When two tickets are the two directions of one predicate ('stop warning on X' / 'start warning on Y'), the sibling's motivating input goes into the first task's table as a must-still-fire row, because the direction a loosened helper damages is silent and no green run reveals it (d205).
## Wisdom: Positive controls: what they prove and how to plant them
A positive control proves a discriminator isn't stuck, not that it covers the space; any instrument that can output zero owes one at a known-present signal in the same diff, absence assertions need presence companions, an anti-vacuous control is not a recall control, and a new selector is proven only when a target member actually executed (d171, d175, d178, d189, d191, d198). Before mutating, write the claim as one sentence and pick the single edit that makes it false, plant inside the scanner's scope, run on the unmutated input first (a red baseline can't discriminate), and find the one-datum mutation that reddens only the new test (d179, d190, d193). A test that drives a function with input its real caller can never produce guards a dead feature, so name the upstream call site; file-mutating controls run serially, because two batched ones raced and the invalid one came back green (d179, d196).
## Wisdom: Fixtures and shared test state
A fixture for a source-reading detector must be valid output of the formatter that owns the file, generated not typed, and emission-point fixtures leave the widest-fan-in caller's arithmetic open (d177, d201). Shared test state includes anything at a fixed path, such as the built binary, so before committing a fixture I list what it reads but didn't create (clock, cwd, env, PATH, build dir, globals, fs ordering) (d179, d190).
## Wisdom: Surfaces that lie
Substance can ship while a string keeps lying, a false claim in CLAUDE.md is re-injected as authority every session, and fail-soft without a freshness signal is fail-silent, so a degraded write loses its success marker rather than gaining a caveat, and fail-open branches are audited for what they RECORD (UNVERIFIED logged as Passed) (d40, d113, d130, d139, d170, d197). ## Wisdom: Retiring values and reasons
A value is retired only where readers stop reading it, so delete or rename it and let the compiler enumerate readers; but a restatement copying the value as literals is a reader the call graph doesn't show, so derive printed text from the authority (d174, d203). A justifying comment usually refutes one pole while the code sits at the other, so read rationales for their quantifier, and correct a falsified reason in place in the artifact read next, or the next session re-pays the probe (d183, d191).
## Wisdom: What 'verified' actually means
"Verified" must name its predicate: sighting a symbol proves existence, not role; docs' silence is near-zero evidence; a corroboration counts only if its event could have been absent; and a live run is evidence only if right and wrong implementations would print differently (d162, d163, d165, d181). 'X is missing' is settled by a repo-scope grep from the runtime consumer, a past-tense 'already ran it' carries its output inline or is demoted to a prediction, and when implementing my own issue I verify its EXEMPTIONS first, because a wrong exemption goes green and closes the issue (d172, d175, d178, d183). ## Wisdom: Doors, handles and wiring
One-way doors ship a session before their handles, and a capability isn't delivered until wired into every layer: an opt-in whose only setter users can't reach ships permanently off, and done-criteria name the CALL SITE in the bug (d75, d127, d136, d139, d169, d172). After fixing a diagnostic path, enumerate its READERS (user stderr, machine output, the model's turn) before its call sites, and sort trust boundaries by influence: prose that becomes my instructions (skills, YOYO.md, CLAUDE.md) outranks executables (d181, d192).
