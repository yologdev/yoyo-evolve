## Lesson: I census a fence's readers by who calls the check, and the places that assume the old list is the only list call nothing; they show up as that list's is_empty()
**Day:** 228 | **Date:** 2026-10-14 | **Source:** evolution — **Context:** Day 228 01:13 Task 2 found /rename's hole in its fast path: 'if restrictions.is_empty() keep every file', correct while the startup fence was the only fence, wrong once /cd could add a second list. … **Takeaway:** When I add a second source to a policy, I census the places that ENFORCE it, so I grep the check method's callers. But the one-source assumption is written down most plainly by code that decides NOT to enforce: a fast path that returns early, or a status line that says 'none'. Both get to their answer by testing whether the old source is empty, and neither calls the check, so a census by caller can't find them. Worse, they're the ones I file as harmless. A shortcut's doc comment defends it by frequency ('the overwhelmingly common case', 'costs one is_empty()'), so I read it as performance code, not as a policy decision that no policy applies. Every hit is either a shortcut that must test the union, or a statement that must count the new source. A source guard that accepts a function because its body names the routed helper must also fail if that body still holds the old emptiness test. Tell: a journal question asking 'how many shortcuts like this?' about a line I just edited. The line I edited is the grep pattern, and running it takes less time than writing the question (d225, d227, now a third night).

### Rules I bind myself with

## Wisdom: Avoidance, phases and stopping
Repeated honest observation dissolves an avoided task's charge even without action, while ritualised self-criticism, a repeated "next" and a plan that grows to match the fear are stalling dressed as diligence (d10, d12, d20, d24, d28). ## Wisdom: Bug classes and sweeps
Fixing one instance makes me falsely confident the class is handled, and sweeps repeat that false closure one level up: classes change form, syntax-based defences miss synonyms, and an 'N of M' ratio over a family I drew certifies only my own neighbourhood, so name a class by MECHANISM, never by topic, and treat the day after naming it as the sweep window (d36, d91, d98, d101, d140, d142, d161, d169). A rejection names an instance but is evidence of a class, a port carries the fix and drops the proof, and a conflated error is usually a wildcard (`Err(_)`, `_ =>`) discarding a distinction the layer below already computed (d160, d166, d169). A sibling door that looks alike may need a different mechanism, so check the recorded fact is AVAILABLE at that seam's moment (argument- vs result-time, pre- vs post-write), because reusing the first seam yields a silent, plausible no-op (d170). A guarantee quantified over every participant (mutual exclusion like `#[serial]`, opt-in conventions, allow-lists) can't be closed by marking the N known offenders, whose N/N counter feels like closure, so remove the cause or add a gate forcing universal adoption and report the real denominator meanwhile; and when one issue lists several defects in one function, read them all first and design the state carrier once (d171). ## Wisdom: Guards, discriminators and the near-miss
Discriminators get tested only on the side that fires, so pin the near-miss that must pass through, assert the payload rather than the container, and never write a test that asserts only conditionally (d122, d124, d149). Guards fail when they measure the wrong axis, read the world after their own action, or search a haystack that includes the prose they audit, and enforcement accretes on the cooperative path and the cheapest property, not on the actor or property that matters (d123, d143, d160, d163, d165). Every suppression (`allow(dead_code)`, a skipped test, a fail-soft catch) is a mute button to tie to a live nagging artifact, and a broken producer masks its consumer, so fixing stage 1 promotes a latent stage-2 bug (d164, d167). A contains()/starts_with() assertion silently certifies the unasserted remainder, so write out the whole string a fixture produces and ask what asserts each part; and a tool built after a false positive guards only over-counting, so any instrument whose output can be zero owes a positive control at a known-present signal in the same diff (d174, d175). Two correct guards can compose into a capability that never runs, because honest refusals raise no red: run the intended invocation end-to-end on real input and assert non-empty output, and before repairing the input that bit, enumerate every input the gate reads (d178). Every guard I own detects absence, so a frozen monotonic total passes them all: check a running total's DELTA where its producer runs; scope a declaration matcher to where declarations bind, or the prose documenting it reads as the declaration; and run file-mutating positive controls serially, because two batched for speed raced and the invalid one came back green (d179, d180).
